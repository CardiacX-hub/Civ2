# Commercial release review — 2026-10-06

This is a source review and local functional check, not a legal clearance or a production penetration/load test. The author confirmed Frontier is their own game. No assets were replaced with assets from another commercial game.

## Completed checks and fixes

- **Dependencies:** `package.json` has no npm runtime dependencies. The Node server uses built-in HTTP, filesystem, compression, VM and crypto modules. Playwright and Chromium are optional artwork/test tools, not shipped game dependencies.
- **Artwork:** `assets/frontier-*.webp` and `assets/world-*.webp` are generated from the author's Frontier renderer plus Kingdoms mesh additions. Their provenance is recorded in `tools/frontier-source.js`, `tools/frontier-art-extension.js` and `tools/render-art.cjs`. This review cannot independently establish ownership of every upstream component of Frontier; retain your source/project records and any contractor agreements.
- **Third-party notices:** the bundled renderer identifies Three.js, Copyright 2010–2023 Three.js Authors, MIT. The full MIT notice is now in `licenses/Three-MIT.txt`. Cinzel and Inter are locally hosted, with original SIL OFL notices in `licenses/`. These licenses permit commercial use subject to their conditions. The game links to notices in Settings. Include the licenses folder with source/distributed bundles. No new license grant for your own game has been added.
- **External services:** no payment API, analytics, ads, accounts, third-party gameplay API, or API key is needed. Gameplay calls only the multiplayer server chosen by the player (`/healthz` and `/api/lobbies/...`). Font requests to Google were removed. A Render deployment link opens only when clicked. Hosting providers can still process/log requests and IP addresses.
- **Secrets:** scanned tracked textual files and source/configuration Git history for common credential signatures. No matching API key or private key was identified. This is a signature scan, not proof that all possible secrets are absent. Administrative codes are public single-player features, not credentials; multiplayer refuses their use and the server disables administrative resources.
- **Multiplayer:** server-authoritative orders validate ownership, visible targets, construction, research and training. Random lobby/session credentials, scrypt passcode hashes, constant-time comparisons, input size limits, join-attempt limits, request budgets, command budgets and lobby/match caps are present. Added a stricter budget for expensive create/join requests and privacy/security response headers. Visible enemies no longer expose private production queues, research plans or rally orders in snapshots. No player tokens or passcodes are included in public lobby views.
- **Learning/accessibility:** added a replayable, ten-lesson guided practice tutorial for either faction, with desktop and touch instructions, actual-action progress, skip/exit controls and screen-reader announcements. Existing configurable keybindings, distinct unit silhouettes, faction colors and mobile panels remain available. Basic privacy information and attribution are available in Settings.

## Decisions and work still needed before charging customers

| Area | Finding / next step |
| --- | --- |
| Commercial hosting | GitHub's official Pages limits prohibit use primarily for online business, commerce, or commercial SaaS. Move the paid product to appropriate hosting; a storefront/demo may require separate assessment. See https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits (official source checked through GitHub's docs repository). |
| Multiplayer operations | `render.yaml` currently selects the free plan. Choose an appropriate paid plan before promising availability; confirm current pricing, terms, backups and support in your Render account. The live Render configuration/logs were not accessible for this review. |
| Reliability | Rooms and matches are memory-only: restarts lose them. No account recovery, durable saves, match reconnection guarantee, matchmaking, monitoring dashboard or crash reporting. Add these according to what you intend to sell. |
| Scale / abuse | Six active matches and 30 rooms are configured caps, not validated capacity. Load-test realistic four-player games before setting a player/service promise. Passcode scrypt and simulation share the Node event loop. Edge rate limiting / asynchronous password work and trusted-proxy IP handling need production assessment. No network penetration test was performed. |
| Product quality | No save/load or game audio. Test balance, long matches, performance on low-end phones and browsers beyond the tested Chromium desktop/touch viewports. Add audio/music only with commercial rights. Automated tests are regression evidence, not broad usability testing. |
| Accessibility | Canvas units are not exposed as a fully accessible game interface. Color-vision options, scalable text, remappable camera controls, reduced-motion options, audio cues and assistive-technology gameplay need further work/testing. |
| Legal / storefront | Choose your storefront, distribution license/EULA, price, support contact, privacy policy and refund/tax arrangements. The in-game privacy summary describes current behavior; it is not a jurisdiction-specific legal policy. Revisit it if you add payments, accounts, analytics or advertising. |
| Naming / ownership | A public GitHub repository does not itself transfer copyright, but browsers download client code/assets; obfuscation is not ownership protection. Review the game title for trademark conflicts and document ownership of any contributions. Original ownership does not establish trademark clearance. |

## Tutorial behavior

Choose **GUIDED TUTORIAL · LEARN TO PLAY** on the main menu. Practice supplies 1,200 gold and lumber, disables AI attacks and administrative resource mode, and shortens practice construction to 12 seconds. It teaches selection, movement, delivered lumber/gold, recruitment, construction, infantry production, research, attack and Stop. A Harvest Guild and a passive practice enemy are supplied when their lessons begin. Ordinary campaigns and server multiplayer retain their existing resources, timing and opponents. You may skip lessons, continue practicing or exit and restart.

## Validation for this update

- Node regression suite: 116 tests, including a full tutorial playthrough through actual resource delivery, construction, research and combat; multiplayer ownership, passcodes, AI mixtures, queue privacy and request limits.
- Chromium browser checks: desktop 1400×1000 and touch 390×844. Tutorial start, selection/move progress, skip/completion/exit and campaign reset passed. No JavaScript errors, no horizontal overflow, and no external browser requests during these checks. Local font loading passed. This does not establish full screen-reader or cross-browser accessibility.
- Local server: tutorial script, font MIME type, license notices and health/API behavior exercised by HTTP tests. The public Render health endpoint returned HTTP 200, protocol 1, four-player capacity and AI support; its game page showed build `20261006-steel-and-scales` before publication of this update. Render account settings, pricing plan, logs and runtime capacity were not inspected.
